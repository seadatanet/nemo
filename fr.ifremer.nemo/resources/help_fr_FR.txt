Pour plus de détails, se référer au manuel utilisateur de NEMO.

==MODELE============================

1/ Modèle/Ouvrir un modèle : charge un modèle existant, seulement si le type de fichier et l'emplacement du ou des fichiers a tété saisi au préalable.
2/ Modèle/Enregistrer le modèle : sauve le modèle au format XML dans le répertoire par défaut des modèles défini dans la configuration de NEMO
    Cette fonction n'est possible que si les 4 étapes de description du ou des fichiers ont été réalisées.
3/ Quitter : ferme l'application après demande de confirmation.

==TABLE DE COUPLAGE=================

Ce menu permet la gestion de la table de couplage de NEMO qui permet la génération du fichier de mapping utilisé par le Download Manager de SeaDataNet 
pour faire la correspondance entre un LICAL_CDI_ID (un profil vertical, une série temporelle ou une trajectoire) et le fichier contenant ce LOCAL_CDI_ID.
1/ Table de couplage/Importer: importe un fichier de mapping dans la table de couplage de NEMO.
2/ Table de couplage/Exporter: exporte la table de couplage dans un fichier.
3/ Table de couplage/Editer la table de couplage: permet de modifier le contenu de la table de couplage de NEMO : effacer des lignes, insérer de nouvelles lignes, mettre à jour des lignes existantes.

==OPTIONS===========================

1/ Options/Configurer: définit la configuration of NEMO comme par exemple les valeurs par défaut pour des informations nécessaires à NEMO, l'adresse des web services, le mapping des flags de Qc, ...
2/ Options/Mise à jour constantes : Met à jour NEMO avec les dernières version des listes de valeurs nécessaires (EDMO, liste de vocabulaires de SeaDataNet, ...).

==FICHIER===========================

==Partie gauche de l'écran :
1/ Sélectionner le type de fichier que vous souhaitez reformatter.
2/ Puis cliquer sur "Parcourir" pour choisir le fichier ou le répertoire.
3/ Si nécessaire, charger un modèle à l'aide du menu "Modèle/Ouvrir un modèle" et sélectionner le fichier XML correspondant.
4/ Si le fichier en entrée contient des séparateurs, cliquer sur "Séparateur" et choisissez le séparateur qui convient.
5/ Sélectionner le type de données traitées : profil vertical, série temporelle ou trajectoire.

==Partie droite de l'écran :
Une fois que le type de fichier et le fichier ou répertoire ont été choisi, la description de fichier apparaît sur la droite de l'écran de NEMO.
 - Bouton "Valider étape" : Une étape doit être validée avant de passer à la suivante.
 - bouton "Reset" : efface toutes les valeurs de l'étape courante.

4 parties : Cliquer sur chaque partie pour modifier les valeurs si nécessaire

1/ Entête de fichier : Ce champ décrit le nombre de lignes de l'entête de fichier, il n’est accessible que dans le cas d'un fichier multi-stations. 
    L'entête fichier correspond aux lignes relatives à l'ensemble des stations du fichier qui ne sont pas répétées, pour chaque station, dans le reste du fichier.
    
2/ Entête station : Ce champ décrit le nombre de lignes de l'entête station ou (exclusif) un indicateur de fin d'en-tête station. 
    Une entête station est un ensemble de lignes contenant des information sur une station.
    Ces lignes sont écrites avant les lignes de données, elles sont répétées pour chaque station.
    + Le nombre de lignes de l'entête station peut être entré manuellement ou sélectionné dans la partie gauche de l'écran et inséré à l'aide du bouton "Injecter". 
    + L’indicateur de fin de l'en-tête station peut être entré manuellement ou sélectionné dans la partie gauche de l'écran et inséré à l'aide du bouton "Injecter". 
      Cet indicateur peut être accompagné d'un nombre de lignes (égal à 0 par défaut) correspondant au nombre de ligne entre l'indicateur de fin de station et la première ligne de données.
    
3/ Fin de station : Ce champ décrit le nombre de lignes de la fin de station.
    Ces lignes sont généralement présentent quand il s'agit d'un fichier multi-stations et que plusieurs lignes séparent les données d'une station de l'en-tête de la station suivante.
    La ligne contenant l'indicateur de fin de données ne doit pas être prise en compte dans ce nombre de lignes de fin de station.
       
4/ Indicateur de fin de données : Ce champ décrit l'indicateur de fin des données mesurées.
    - Pour les fichiers mono-station, la plupart du temps, la fin de fichier (EOF) est l'indicateur de fin de données, mais il peut y avoir une ligne vide ou une ligne avec un texte spécifique qui indique la fin des mesures.
    - Pour les fichiers multi-stations, NEMO a besoin d'un séparateur entre les stations pour pouvoir reconnaître le changement de station.
      Cet indicateur peut être une ligne vide ou un texte spécifique, qui peut se trouver sur la première ligne de la station suivante (dans ce cas il est nécessaire de cocher le champ correspondant.
      Par exemple, pour les fichiers au format MEDATLAS, l'indicateur de fin de données est la ligne de valeurs par défaut commençant par exemple par "-999.9 99.999". 
      Il n'est pas nécessaire de taper toutes la lignes, les premiers caractères significatifs suffisent.
      
    Pour chacune de ces parties les champs peuvent peut être soit entrés manuellement ou sélectionnés dans la partie gauche de l'écran et insérés à l'aide du bouton "Injecter".
    
==Partie inférieure de l'écran
3 onglets sont accessibles

1/ Onglet Erreurs : Cet onglet donne des informations sur le déroulement de la validation de l'étape.
    Si l'information est une erreur elle est écrite en rouge, sinon elle est écrite en vert.
    
2/ Onglet Infos : Cet onglet donne des informations sur le fichier ou le répertoire d'entrée, et aussi sur le modèle utilisé (s'il y en a un).

3/ Onglet aide : Cet onglet affiche l'aide en ligne, à chaque étape.

 - Bouton "Valider étape" : Une étape doit être validée avant de passer à la suivante.
 - bouton "Reset" : efface toutes les valeurs de l'étape courante.

3 possibilités à cette étape: 

1/ Entrer les valeurs manuellement 
2/ Interroger le Web service en cliquant sur "Initialisation serveur" (pour IFREMER seulement)
3/ Importer les informations à partir d'un fichier XML de rapport de campagne (CSR de SeaDataNet) en cliquant sur "Initialisation XML".

6 sections : Cliquer sur chaque section pour modifier les valeurs si nécessaire

5/ Type de données : code ROSCOP des types de données (SeaDataNet Liste C77)
6/ Commentaires éventuels : Texte libre pour décrire par exemple les méthodes de mesure des paramètres

==DESCRIPTION DE STATION=============================

Cette étape sert à NEMO pour retrouver les informations obligatoire ou importantes des en-têtes station du (ou des) fichier(s).
Cette information change suivant si l'on traite des profils verticaux, des séries temporelles ou des trajectoires. 

==Pour les profils verticaux============
12 sections sont affichées : Cliquer sur chaque partie pour modifier les valeurs si nécessaire.
Les champs obligatoires sont : Numéro de station, Type de données, Heure, Date, Latitude et Longitude. 

1/ Numéro de station : Le numéro des stations peut être incrémenté à partir d'un nombre donné par l'utilisateur ou il peut être lu dans l'en-tête station et saisi dans NEMO à l'aide des boutons injecter et Test.
          Si le numéro des stations est donné dans le nom des fichiers en entrée, mettre 0 dans champ ligne, et mettre les rang des premier et dernier caractères du numéro de station dans le nom du fichier.
          exemple : nom de fichier en entrée xxxxyyyy1234.dat, le numéro de station est entre les caractères 9 et 12 du nom de fichier, 
                    mettre respectivement 0, 9 et 12 dans les champs Ligne, Début et fin de la section "Numéro de station".  

2/ Type de données : C'est le code ROSCOP de l'instrument utilisé pour collecter les données (H10 - Ctd par exemple), les codes proposés sont sélectionnés dans la liste des Types de données 
                     de l'étape précédente (Description de campagne).
                     Si l'utilisateur travaille sur une collection de fichiers, ce champ n'est pas accessible ; le type de données est demandé au moment de la conversion.

3/ Historique Acquisition : 2 lignes peuvent être utilisées pour mettre des commentaires sur la méthode et/ou l'instrument utilisé pour la collecte des données
			    Ces lignes peuvent être saisies manuellement ou lues dans le fichier à l'aide du bouton "Injecter".

4/ Commentaire : Commentaire sur la station, pas de limitation sur le nombre de lignes. Ce commentaire peut être saisies manuellement ou lues dans le fichier à l'aide du bouton "Injecter".
                 Si le commentaire est sur plusieurs lignes de longueurs différentes, cocher le champ "Position fin de ligne variable".

5/ Echantillon de surface : Même principe que pour "Historique Acquisition", 2 lignes de commentaires sur les éventuels échantillons de surface.

6/ Décalage/TU : Ce champ sert à gérer les heures non TU dans les fichiers en entrée.
                 Si l'heure de la station est en TU-5 dans les fichiers en entrée, mettre 5 (ou utiliser le bouton injecter pour lire la valeur dans le fichier) dans le champ prévu.
                 NEMO ajoutera alors 5 heures à l'heure lue dans le fichier. Si l'heure en entrée est à TU+5, mettre -5 dans le champ.
                 La valeur par défaut est fixée à 0.

7/ Heure : Entrer le format de l'heure du fichier en entrée, puis, sélectionner l'heure dans le fichier, appuyer sur le bouton "Injecter", puis sur le bouton Test pour vérifier la valeur.
           Le format peut être sélectionné dans la liste, ou saisi par l'utilisateur en utilisant les valeurs suivantes :
               hh: heure exprimée sur 2 caractères (hh24 indique une heure comprise entre 0 et 23).
               mm: minutes exprimée sur 2 caractères (entre 0 et 59)
               ccc: centième d'heure sur 1 à 7 caractères (exemple : format hh24.ccc, valeur = 17.125, heure = 17:07:30.000)
               ss: secondes exprimées sur 2 caractères (entre 0 et 59)
               PM: heure au format anglo-saxon (PM et AM)
               ttttt: secondes exprimées sur 1 à 5 caractères (pour les heures exprimées en secondes, exemple : format tttt, valeur=3610, heure = 01:00:10.00)
               D.dddddd: heure des jours juliens chronoliques (utilisée par exemple dans le format ODV)
                   exemple : si la date à lire est la suivante : 2454972.09687, 
                               pour le jour il faut lire 2454972.0, format DDDDDDD.d
                               pour l'heure il faut lire 2.09687    format D.ddddd
               

8/ Date : Entrer le format de la date du fichier en entrée, puis, sélectionner l'heure dans le fichier, appuyer sur le bouton "Injecter", puis sur le bouton Test pour vérifier la valeur.
          Le format peut être sélectionné dans la liste, ou saisi par l'utilisateur en utilisant les valeurs suivantes :
               YY or YYYY: année sur 2 ou 4 caractères
               MM: mois sur 2 caractères (1 à 12)
               MMM: mois sur 3 caractères alphabétiques (JAN,FEB,MAR,APR,MAY,JUN,JUL,AGU,SEP,OCT,NOV,DEC)
               DD: Jour dans le mois sur 2 caractères (1 à 31)
	       	   DDDDDDD.d: Jour julien chronologique de (utilisé dans le format ODV)
                  exemple : si la date à lire est la suivante : 2454972.09687, 
                               pour le jour il faut lire 2454972.0, format DDDDDDD.d
                               pour l'heure il faut lire 2.09687    format D.ddddd

9-10/ Latitude et Longitude : Entrer le format de la latitude ou de la longitude du fichier en entrée, puis, sélectionner l'heure dans le fichier, appuyer sur le bouton "Injecter", puis sur le bouton Test pour vérifier la valeur.
      Le format peut être sélectionné dans la liste, ou saisi par l'utilisateur en utilisant les valeurs suivantes :
               N: désigne l'hémisphère. Les valeurs en entrée doivent être égales à N ou S pour les latitudes et W ou E dans le cas des longitudes
               +: désigne l'hémisphère. Les valeurs en entrée doivent être égales à ' ' ou '+' pour exprimer une latitude Nord, et une longitude Est ou
                                                                                          à'-' pour exprimer une latitude Sud, et une longitude Ouest
               DDD or DD or D: Degrés (0 à 90 pour la latitude, 0 à 180 pour la longitude)
               DDD.ddd or DD.ddd: Degrés décimaux. Le nombre maximum de D est 3 pour la longitude et 2 pour la latitude
                    le nombre de 'd' exprime le nombre de décimales.
               MM: Minutes (0 à 59)
               MM.mm: Minutes décimales. Le nombre de 'm' exprime le nombre de décimales.
               SS: Seconds (0 à 59)

               Cliquer sur "Position de fin de ligne variable" si toutes les latitudes ou longitudes des stations en entrée ne se termine pas à la même position 
               (cela arrive souvent avec si les zéros non significatifs de fin ne sont pas écrits).

11/ Profondeur : Profondeur de l'océan au point de la station en mètres. Cette valeur peut être saisie manuellement ou lue dans le fichier à l'aide du bouton "Injecter", puis testée à l'aide du bouton "Test".
                 Cliquer sur "Position de fin de ligne variable" si toutes les profondeurs des stations en entrée ne se termine pas à la même position.

12/ QC flags : Flags qualités sur les méta-données de l'entête station qui peuvent exister en entrée (cas du format MEDATLAS, par exemple).
               Ces flags qualité sont utilisés en sortie uniquement dans le format MEDATLAS, ils concernent la date/heure, la latitude, la longitude et la profondeur.

==Pour les séries temporelles ==========
6 sections supplémentaires sont affichées.
Les champs obligatoires sont : Numéro de station, Type de données, Heure, Date, Latitude, Longitude, et Profondeur du capteur.

13-14/ Latitude de fin et Longitude de fin: latitude et longitude à la date de fin des séries temporelles.
          Si rien n'est saisi, les valeurs sont les mêmes que celles de Latitude et Longitude qui sont les positions à la date de début des séries temporelles.
          Les valeurs autorisées sont les mêmes que pour les champs Latitude et Longitude décrits pour les profils verticaux.

15/ Profondeur de fin : Profondeur de l'océan au point de la station en mètres, à la date de fin des séries temporelles.
               Si rien n'est saisi, les valeurs sont les mêmes que celles du champ "Profondeur" qui est la profondeur à la date de début des séries temporelles.
               La saisie se fait de la m^me façon que dans le champ "Profondeur" décrit pour les profils verticaux. 
          
16/ Profondeur du capteur : Profondeur du capteur mesurant les données, elle doit être donnée en mètres. Ce champ peut être renseigné manuellement ou automatiquement en utilisant le bouton « Injecter ».
 
17/ Déclinaison magnétique : Déclinaison magnétique à la position des séries temporelles, utile pour les courantomètres.
          C’est un enter signé : une déclinaison magnétique de W007 doit être saisie  -7 et E005 doit être saisie +5 or 5.
          Ce champ peut être renseigné manuellement ou automatiquement en utilisant le bouton « Injecter ».

18/ Fréquence d'échantillonnage : Fréquence d'échantillonnage des capteurs. Ce champ peut être renseigné manuellement ou automatiquement.
          NEMO le calcule automatiquement (et empêche sa saisie) si la date et l'heure sont lues dans la première lige de données.
          L'unité de la fréquence d'échantillonnage est la seconde. Si elle n'est pas données en secondes dans les fichiers en entrée, elle doit être convertie en utilisant le champ "Formule de conversion" 
          (exemple : si la fréquence d'échantillonnage est données en heure dans les fichiers en entrée, mettre *3600 dans la formule de conversion).

== Pour les trajectoires ==========
14 sections peuvent être renseignées, elles ont déjà été décrites pour les profils verticaux et les séries temporelles.
les champs obligatoires sont : Numéro de station, Type de données, Heure, Date, Latitude et Longitude.

    Numéro de station : dans le format ODV, une trajectoire est considérée comme une série de stations ayant chacune un seul point de mesure, mais
                        ayant toute le même LOCAL_CDI_ID.
                        En MEDATLAS, une trajectoire est une seule station dans laquelle la latitude et la longitude sont considérées comme des paramètres mesurés. 
                        Le numéro de station ne peut pas être incrémental.

==DESCRIPTION DES DONNEES=============================================

Cette étape permet d'indiquer à NEMO où trouver les valeurs des paramètres mesurés dans les fichiers en entrée.
Cette information concerne le nom,l'unité, les valeurs par défaut en entrée et en sortie et le format de sortie des paramètres mesurés 

- Pour les profils verticaux, PRES (pour Pression de l'eau de mer, en décibars) est un paramètre obligatoire.
  Il est mis par défaut dans NEMO et il ne peut pas être effacé (c'est un paramètre obligatoire dans le format MEDATLAS).

- Pour les séries temporelles, la date et l'heure des mesures sont mises automatiquement dans les fichiers de sortie,
  il ne faut pas les décrire dans la description des données.

- Pour les trajectoire la date, l'heure, la latitude, la longitude et la profondeur du fond (si elle existe) des points de mesures
  sont mises automatiquement dans les fichiers de sortie, il ne faut pas les décrire dans la description des données.

==Un click droit sur le tableau des paramètres mesurés ouvre le Menu contenant les choix suivants :
===================================================================================================
- Injecter début/fin:
   Pour insérer les caractères début et fin du paramètre mesuré dans la ligne de données du fichier en entrée.
   La valeur du paramètre doit être surlignée dans le fichier en entrée, avant d'utiliser ce choix du menu.

- Maj. champ test:
   Pour afficher les valeurs lues dans les champs tests incluant :"Test" (pour les paramètres mesurés), "Test (entrée)" 
   pour les valeurs des flags qualités lue dans le fichier en entrée et "Test (sortie)" Pour les valeurs des flags qualités écrites dans les fichiers en sortie.
   
- Liste de paramètres:
   Pour ajouter un paramètre dans le tableau des paramètres mesurés. Cette liste est la liste P091 de SeaDataNet et correspond aux codes MEDATLAS des paramètres.

- Monter paramètre sélectionné:
   Pour déplacer un paramètre vers le haut, dans le tableau des paramètres mesurés. 
   L'ordre des paramètres dans le tableau est l'ordre des paramètres dans le fichier de sortie.

- Descendre paramètre sélectionné:
   Pour déplacer un paramètre vers le bas, dans le tableau des paramètres mesurés. 
   L'ordre des paramètres dans le tableau est l'ordre des paramètres dans le fichier de sortie.

- Supprimer paramètre sélectionné:
   Pour supprimer un paramètre du tableau des paramètres mesurés.

- Injecter flag:
   Pour insérer les caractères début et fin du flag qualité du paramètre mesuré dans la ligne de données du fichier en entrée.
   La valeur du flag qualité doit être surlignée dans le fichier en entrée, avant d'utiliser ce choix du menu.
   la conversion d'échelle de flags est celle utilisée à l'étape précédente (Description de station, section QC flags).

- Supprimer flag:
   Pour effacer l'information sur le flag qualité du paramètre sélectionné.

==Le tableau des paramètres mesurés contient les colonnes suivantes :
=====================================================================
- Code : code MEDATLAS du paramètre

- Unité : unité MEDATLAS du paramètre

- Conversion : pour insérer une formule de conversion qui doit être de la forme : x*1000+3; où x est la valeur lue dans le fichier en entrée.

- Test : Ce champ affiche la valeur telle qu'elle sera écrite dans le fichier en sortie.
         Pour rentrer des valeurs dans ce champ, clic droit dans le tableau et choisir "Maj. champ test" dans le menu;
         Les champs début et fin, format et val def entrée doivent être renseignés avant d'actionner la mise à jour du champ test.

- Début - Fin : Ces champs indiquent les caractères début et fin du paramètre sur la ligne de données du fichier en entrée.
                Pour rentrer des valeurs dans ces champs, surligner la valeur du paramètre dans le fichier en entrée, puis clic droit dans le tableau et choisir "Injecter début/fin" dans le menu.

- Format : Ce champ décrit le format de sortie du paramètre mesuré.
           Exemples de formats corrects : %3d pour 150, %+4d pour +150 ou -150, %6.3f pour 12.124, %+7.5f pour +1.12345 ou -1.12345

- Val. def entrée : Ce champ décrit la valeur que l'on trouve dans les fichiers en entrée quand le paramètre n'est pas mesuré.
                    Cette valeur par défaut est de type alphanumérique. Si la valeur est vide dans le fichier en entrée (comme dans ODV, par exemple), laisser ce champ vide également.

- Val. def. sortie : Ce champ décrit la valeur que l'on trouve dans les fichiers en sortie quand le paramètre n'est pas mesuré.
                     Pour MEDATLAS, la valeur par défaut en sortie doit être un nombre (une suite de 9) au m^me format que le paramètre mesuré, décrit dans la colonne format.

- Test (Entrée) : Ce champ décrit la valeur du flag qualité dans le fichier en entrée.

- Test (Sortie) : Ce champ décrit la valeur de flag correspondante telle quelle sera écrite dans le fichier en sortie.

     Pour entrer des valeurs dans ces 2 derniers champs, clic droit dans le tableau et choisir "Maj. champ test" dans le menu; 
     les champs Début (flag) et Fin (flag) doivent avoir été renseignés au préalable.

- Début (Flag) - Fin (Flag): Ces champs indiquent les caractères début et fin du flag qualité du paramètre sur la ligne de données du fichier en entrée.
                 Pour rentrer des valeurs dans ces champs, surligner la valeur du flag qualité dans le fichier en entrée, puis clic droit dans le tableau et choisir "Injecter flag" dans le menu.

==CONVERSION==

Dernière étape de NEMO, une fois que la description des fichiers en entrée est complète, il est possible de convertir les fichiers au format ODV ou au format MEDATLAS.

Cette étape de conversion génère :
- Le ou les fichiers de sortie au format demandé.
- If "Création d'un résumé pour le CDI de SeaDataNet" est coché dans la configuration de NEMO, un fichier de résumé pour le CDI est créé, pendant le processus de conversion.
  C'est un fichier au format (CSV) qui doit être converti en fichier Excel pour être directement utilisable par le logiciel MIKADO pour générer les descriptions XML des
  stations converties au format ODV et/ou au format MEDATLAS. 
- If "Création du mapping pour le download manager de SeaDataNet” est coché dans la configuration de NEMO, l'information est insérée dans la table de couplage de NEMO pour toute les stations converties au format ODV et/ou au format MEDATLAS. 
  
Si l'utilisateur veut convertir ses données aux 2 formats (MEDATLAS et ODV) il peut lancer les 2 conversions de façon consécutives sans repasser par toutes les étapes de NEMO.

La conversion est divisée en 2 étapes:
1-conversion du fichier en mémoire : la conversion en mémoire peut être interrompue à tout moment.
2-écriture du ou des fichier(s) converti(s) sur disque : une fois commencée, cette écriture ne peut pas être interrompue.
