Here is a fast overview of the different steps a user will have to complete before converting a file.

 

MENU

  1. Model/Open model : loads a model only if a cruise has previously been opened.
  2. Model/Save model : creates on the disk a XML-type file corresponding to the values entered in the different steps. It is fonctional only once the first 4 steps have been validated.
  3. Quit : shuts down the application after having been asked to confirm.

 

FILE DESCRIPTION

  1. 'file' or 'directory' Selection by ticking or not 'temporal series'.
  2. 'Browse' Button  and choose a file or directory.
  3. If needed, load a model via the model/ open a model menu and by choosing the XML file of the model corresponding to the current cruise.
  4. The description of file zone appears. Click on each section and modify the values.
  5. To indicate a number of lines, highlight with the mouse the lines concerned on the left part of the window then click on the butten 'inject' of the considered section.
  6. The end of data pattern can be entered by the user.

END will be translated by NEMO into ^END$

EOF will be translated by NEMO into ^$

  1. These values can be found again after the loading of a model.
  2. The 'info' tab resumes the main information of the cruise's files and the loaded model.
  3. The 'help' tab displays at each step the corresponding help.
  4. Once the values fulfilled, click on 'validate' to turn to the next step. If some mistakes have occured, red messages will appear in the 'error' tab.
  5. The 'reset' button will erase all the values of the current step.

 

CRUISE DESCRIPTION

3 possibilities for fulfilling this step: entering all the values manually, asking the webservices or loading a XML file.

  1. Manually : filling the 'reference', 'location', 'data source '  and 'possible comments' sections. For the 'archiving centre' section , choose confidentiality in the combo list. For the 'data type' section, a right click on the blank table makes a menu appear. It will enable to add a new type ('list Selection') to move or erase the selected type.  Don't try to left-click to choose a line then to right-click to make the menu appear. On the contrary do a right-clik directly, otherwise you will start the edition mode. The type of data selection's window enables to make searches on both the code and the name of the type
  2. Webservices, 'server initialisation' button : the survey's selection window enables to make searches using the code or the name of the cruise
  3. XML file, 'XML initialisation' button : choose a cruise XML file.

 

STATION DESCRIPTION

It's the same principle than for the previous steps, only here some values to inject ask values on 'line', 'start' and 'end'. In the case of a cruise file, always carry out the injections on the first station !

In any case, the selection will have to be limited to a single line (date, time, latitude, depth, etc.) with the exception of the 'comment' where the possibility of highlighting several lines is proposed.

For the time, date, latitude and longitude formats, you can enter your own formats.

If station's number is located within the filename, use 0 as line number

 

TIME / DATE FORMATS

  • yy or yyyy : the year expressed in 2 or 4 digits
  • MM : month expressed in 2 digits
  • dd : day in the month expressed in 2 digits
  • hh : hour expressed in 2 digits
  • mm : minutes in the time expressed in 2 digits
  • ss : seconds expressed in 2 digits

The following restrictions are associated to these formats:

The values are completed on the left by a 0 if the value to indicate is under 10 (i.e. : year 2000 -> 00)

The time can be omitted

The order between the date and the time is free (date time, time date)

Any other extra characters can be inserted between the various keys. The same values will be expected at the input and at the output.

Examples:

yyy/MM/dd hh:mm:ss ==> 1986/07/10 09:23:10

hh:mm ==> 09:23

yy-MM-dd ==> 86-07-10

 

LATITUDE / LONGITUDE FORMATS

  • N : expresses an hemisphere. Its value will have to equal N or S in the case of latitudes and W or E in the case of longitudes
  • DDD ou DD : Number of degrees. The number of D must be 3 in the case of longitudes and 2 in the case of latitudes
  • DDD.ddd ou DD.ddd : Degrees in decimal values. The number of D must be 3 in the case of longitudes and 2 in the case of latitudes. The number of 'd' characters expresses the accuracy expected
  • MM : Minutes
  • MM.mm : Minutes in decimal values. The number of 'm' characters expresses the accuracy expected.
  • SS : Seconds
  • +DDD.ddd

The following restrictions are associated to these formats :

The values are completed on the left by an empty space if the value to display doesn't amount to the number of characters expected.

The hemisphere pattern can be found before or after the numeric value

In the case when the degrees are expressed in decimal values, no minute is expected.

In the case when the minutes are expressed in decimal values, no second is expected.

Any other extra characters can be inserted between the various keys. The same values will be expected at the input and at the output.

Examples :

NDDD MM.mm ==> W123 10.25

DDD MM SS N ==> 123 10 30 W

 

DATA DESCRIPTION

It's the same principle than for the type of data: you add here the measured parametres.

Conversion formula should be like x*1000+3 ; with x the value read in file

In the case of a temporal series :

  • DATE, YEAR, MONTH, DAYX, TIME parameters are automatically generated so pay attention not to add them manually.
  • you can choose if the time/date computation is based on the date/hours entered at the Station step and the sampling rate or if the information are included into the line of data  (in which case you need to precise the format).

 

CONVERSION

Choose the output format. You can generate both formats consecutively without revalidating all the steps.

Conversion is divided in two steps:

  1. file conversion into memory : you still can cancel all the conversion process!
  2. file writing on disk : you can't cancel the conversion process no more while this step is loading!
